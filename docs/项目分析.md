# SnowShot / SpringScreen 项目分析

> 分析时间：2026-08-10
> 分析范围：仓库 `D:\SnowShot\snow-shot`，截至 git HEAD `c2ad3772`

## 1. 项目定位

这是一个 **Windows 截图工具** 的二次开发版本，产品名从上游 **SnowShot** 改名为 **SpringScreen（春屏）**。

- **上游来源**：[mg-chao/snow-shot](https://github.com/mg-chao/snow-shot)（GPL-3.0，Rust + Tauri 截图工具）
- **本项目仓库**：[Beet-le/SpringScreen](https://github.com/Beet-le/SpringScreen)
- **核心卖点（README 自述）**：面向**低配置 Windows 设备**深度优化，强调低内存占用、长截图流畅、WebView2 内存管理。
- **产品名 / 标识**：`productName = SpringScreen`，`identifier = XiaoDaShuai`（tauri.conf.json）。

## 2. 技术栈

| 层 | 技术 | 说明 |

| 后端语言 | Rust（Cargo 工作空间，edition 2024） | `rust-version = 1.90` |
| 包管理 | pnpm 10.8.1（前端）/ yarn（Excalidraw 子项目）/ cargo（Rust） | 多包管理器并存 |

> ⚠️ **文档与代码不一致**：`development.md` 仍描述“Next.js + yarn”，但实际已迁移到 **Rsbuild + pnpm**；`package.json` 的 `version` 仍是 `0.0.1`（模板残留），真实版本以 `tauri.conf.json` / `Cargo.toml` 的 **0.7.9-beta** 为准。

## 3. 架构

### 3.1 分层结构
```
前端 SPA (React/TS, Rsbuild)
   │  Tauri IPC（src/commands/*.ts ↔ src-crates/tauri-commands/*）
   ▼
Rust 工作空间（~16 个 crate）
   │  调用
   ▼
原生库 / 系统 API（xcap、device_query、ORT、ffmpeg、enigo、uiautomation、scap…）
```

### 3.2 前端模块（`src/`）
- `pages/`：`home`(空闲页)、`draw`(绘制)、`fullScreenDraw`(全屏绘制)、`fixedContent`(固定内容)、`imageViewer`(图片查看)、`videoRecord`(录屏)、`tools`(工具)、`settings`(设置)、`personalization`(个性化)、`about`(关于) —— 覆盖完整截图工作流。
- `commands/`：按领域拆分（`core/file/ocr/screenshot/scrollScreenshot/videoRecord/webview/plugin/httpServices…`），与 Rust 端 `tauri-commands/*` 一一对应。
- `core/canvas`（`canvasHistory.ts` 撤销重做）、`components/drawCore`（绘图核心）、`components/imageLayer`、`components/translator`（翻译组件）、`contexts/globalContext`、`hooks/`、`services/tools/`、`constants/`、`utils/`、`types/`(命令/组件/上下文类型)。
- 入口 `index.tsx` + `App.tsx`（TanStack Router，`/?route=/xxx` 深链唤起）。

### 3.3 Rust 工作空间（`src-tauri/src-crates/`，~13.5k 行）
按职责拆成约 16 个 crate，结构清晰：

| 分类 | crate |
|------|-------|
| 服务层 | `app-services`（OCR、录屏、热加载、键鼠监听、图片查看、自由拖窗）、`app-scroll-screenshot-service`（滚动截图） |
| IPC 命令 | `tauri-commands/{core,file,ocr,screenshot,scroll-screenshot,http-service}` |
| 平台 | `app-os`（Windows/macOS 效能模式、自启动） |
| 支撑 | `app-utils`（图像/窗口处理）、`app-shared`（共享类型）、`global_state`、`webview`（GPU 零拷贝共享缓冲）、`http-services`、`plugin-service` |
| 入口 | `src/main.rs` → 二进制 `SpringScreen.exe`；库 `snow_shot_lib` |

**关键 Rust 依赖（多数为定制 fork）**：
- `xcap`（mg-chao 定制分支）屏幕捕获；`device_query`（定制分支）键鼠输入监听
- `ort` (ONNX Runtime) + `paddle-ocr-rs` 文字识别（需静态 `onnxruntime.lib`）
- `ffmpeg-sidecar` 屏幕录制；`enigo` 输入模拟（滚轮穿透）；`uiautomation`（Win 自动框选元素）；`scap`（macOS 捕获）
- `image`/`imageproc` 图像处理、`rayon` 并行、`dashmap` 并发、`tokio` 异步

**Release 优化激进**：`opt-level=3` + `lto="fat"` + `panic="abort"` + `strip` + `codegen-units=1`，并关闭溢出检查——明确以“运行时性能 + 体积”优先。

## 4. 核心功能（由 pages + services 推断）

1. **截图**：区域/全屏截图（`screenshot` 命令，基于 xcap）
2. **标注绘制**：截图后自由绘制（定制 Excalidraw + PIXI）
3. **长截图 / 滚动截图**：独立 `scroll-screenshot` 服务与命令
4. **OCR 文字识别**：PaddleOCR via ONNX，本地离线识别
5. **屏幕录制**：ffmpeg-sidecar 调用 FFmpeg CLI
6. **图片查看**：新增 `imageViewer`，支持 PNG/JPEG/WebP/BMP/GIF/TIFF（7 种格式）
7. **固定内容（贴图）**：`fixedContent` 截图固定到桌面
8. **工具 / 设置 / 个性化 / 关于**：设置面板、主题皮肤、插件体系（`plugin-service`）

## 5. 本项目的二次开发重点（相对上游）

从 README 与最近提交（`git log`）可归纳优化方向：
- 重构长截图渲染逻辑，提升滚动/拼接流畅度
- 新增命令行启动：`SpringScreen.exe --open-draw` 直接唤起绘制面板
- 优化 WebView2 内核内存管理，解决内存持续上涨
- 调整 OCR / FFmpeg 资源加载规则，支持读取运行目录内依赖
- 截图固定后支持键盘方向键移动
- 最近提交显示：**禁用了 AI 对话功能**（移除了上游的 AI 聊天，openai 依赖仍保留在 package.json）

- **代码量**：前端 TS/TSX ≈ **62,000 行**；Rust ≈ **13,500 行**；外加 Excalidraw 子项目（外部）。
- **构建产物**：`dist/`（前端构建）、`src-tauri/target`（Rust 构建，4 万+ 文件）。
- **版本**：0.7.9-beta（Cargo / tauri.conf）；`package.json` 版本字段未同步。
- **开发环境（development.md）**：Windows 11 / Node 20.11 / pnpm 10 / yarn 1.22 / Rust 1.84（注意 Cargo.toml 要求 1.90，文档偏低）。

## 7. 值得注意的点 / 风险

1. **`backend/SnowShot.Backend` 为空**：只有 `bin/`、`obj/` 空目录，无源码。疑似早期规划的 .NET 后端被移除或尚未引入；当前功能完全由 Tauri+Rust 承载，该目录可清理或补回说明。
2. **双许可证**：仓库根有 `LICENSE-Commercial` 与 `LICENSE-NonCommercial`，与上游 `LICENSE`(GPL-3.0) 并存——需确认分发/商用时的合规边界（GPL-3.0 与商用许可的冲突）。
3. **文档滞后**：`development.md` 写 Next.js/yarn，实际已用 Rsbuild/pnpm；版本号不一致。
4. **定制 fork 依赖**：xcap、device_query、scap、excalidraw 均为作者定制分支，供应链依赖个人仓库，升级/维护需持续跟进上游。
5. **打包前置条件多**：需手动准备 Excalidraw 子项目、`onnxruntime.lib`、可选 `ffmpeg.exe`，门槛较高。
6. **AI 能力半移除**：`openai` 依赖仍在 `package.json`，但提交显示已禁用 AI 对话，存在无用依赖/死代码清理空间。
